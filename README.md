# asdr_bot — репостер новостей из Telegram-каналов

Собирает новые посты из указанных каналов, **вырезает подписи источника**
(строку вида `Prezident.uz|Facebook|Instagram|YouTube|X`, ссылки на соцсети,
призывы «подпишитесь») и публикует результат в ваш канал — текст, фото, видео,
альбомы, документы.

Пример поста-источника: <https://t.me/shmirziyoyev/35508> — футер со ссылками
на president.uz / Facebook / Instagram / YouTube / X удаляется полностью,
остальной текст и форматирование (жирный, курсив, ссылки по делу) сохраняются.

Рассчитан на **шаред-хостинг**: постоянно висящий процесс не нужен, работает
короткими запусками по cron (или по URL), состояние хранит в SQLite рядом с кодом.

---

## 1. Как это работает

| | |
|---|---|
| Чтение каналов | через MTProto от имени **обычного аккаунта** (Telethon). Бот-API так не умеет: бот видит только те каналы, где он администратор |
| Публикация | от имени того же аккаунта **или** от имени бота (`BOT_TOKEN`, бот — админ вашего канала) |
| Запуск | `python -m asdr poll` — один проход; cron вызывает его раз в N минут |
| Память | `data/asdr.db` — до какого сообщения дочитан каждый канал и что уже опубликовано (дублей не будет) |

## 2. Установка

Нужен Python 3.9+.

```bash
git clone https://github.com/artstudiouzb-gif/asdr_bot.git
cd asdr_bot
pip install --user -r requirements.txt     # на шаред-хостинге именно --user
cp .env.example .env
```

На cPanel: **Setup Python App** → создать приложение (папка `asdr_bot`) →
в разделе Configuration files указать `requirements.txt` → Run Pip Install.
Дальше все команды запускайте из терминала cPanel, предварительно активировав
окружение командой, которую cPanel показывает на странице приложения
(`source /home/USER/virtualenv/asdr_bot/3.11/bin/activate`).

## 3. Настройка

1. Получите `API_ID` и `API_HASH` на <https://my.telegram.org> → **API development tools**.
2. Впишите их в `.env`, укажите каналы:

```env
API_ID=1234567
API_HASH=0123456789abcdef0123456789abcdef
SOURCES=shmirziyoyev, @another_channel
TARGET=@my_news_channel
```

3. Авторизуйтесь и получите строку сессии (спросит телефон, код из Telegram,
   при необходимости пароль 2FA):

```bash
python -m asdr login
```

Скопируйте выданную длинную строку в `.env`:

```env
SESSION=1BQANOTEuMTA4LjU2LjE3M...
```

> Если на хостинге нет интерактивного терминала — выполните `login` на своём
> компьютере и просто перенесите строку `SESSION` в `.env` на хостинге.
> Файл сессии переносить не нужно.

4. Проверьте доступы:

```bash
python -m asdr check
```

Аккаунт должен быть подписан на приватные каналы-источники и иметь право
публикации в `TARGET` (или бот из `BOT_TOKEN` должен быть админом канала).

5. Посмотрите, как отработает очистка, ничего не публикуя:

```bash
python -m asdr poll --dry-run
```

## 4. Запуск по cron (основной режим для шаред-хостинга)

В панели хостинга (Cron Jobs) добавьте задание раз в 5 минут:

```
*/5 * * * * /home/USER/asdr_bot/cron.sh >> /home/USER/asdr_bot/data/cron.log 2>&1
```

Если используется виртуальное окружение cPanel, укажите его python напрямую:

```
*/5 * * * * cd /home/USER/asdr_bot && /home/USER/virtualenv/asdr_bot/3.11/bin/python -m asdr poll >> data/cron.log 2>&1
```

Параллельные запуски безопасны: второй экземпляр видит лок-файл и сразу выходит.
Чтобы хостинг не убил процесс по таймауту, запуск сам завершается по лимитам
`MAX_RUNTIME`, `MAX_POSTS_PER_RUN` — остаток заберётся следующим запуском.

### Если cron умеет только открывать URL

Задайте `WEB_SECRET=длинная_случайная_строка` в `.env` и настройте приложение
(`passenger_wsgi.py` — готовая точка входа для cPanel/Plesk). Дальше cron:

```
*/5 * * * * curl -s "https://ваш-домен/run?key=длинная_случайная_строка"
```

Адреса: `/run` — запустить проход (в фоне), `/run?...&wait=1` — дождаться
результата, `/status` — статистика. Без правильного `key` — 403.

### На VPS (если появится)

```bash
python -m asdr watch --interval 60
```

## 5. Что именно вырезается

| Правило | Настройка |
|---|---|
| Строка-подпись из ссылок на соцсети (`Prezident.uz\|Facebook\|Instagram\|YouTube\|X`) — и в виде ссылок, и в виде `Название (https://...)` | `BLOCKED_DOMAINS` |
| Ссылки на эти домены внутри текста — остаётся только текст | `UNWRAP_BLOCKED_LINKS=true` |
| Строки «подпишитесь на канал», «obuna bo'ling», «subscribe» | `DROP_SUBSCRIBE_LINES=true` |
| Любые свои строки | регулярки в `patterns/drop_lines.txt` |
| Любые фрагменты внутри строк | регулярки в `patterns/remove.txt` |
| Своя подпись в конце | `FOOTER=@my_channel` |

Проверить правила на конкретном посте:

```bash
python -m asdr test post.txt      # или: pbpaste | python -m asdr test
```

Фильтры постов: `INCLUDE_KEYWORDS`, `EXCLUDE_KEYWORDS`, `MIN_TEXT_LENGTH`,
`SKIP_WITHOUT_TEXT`, `SKIP_MEDIA`, `SKIP_FORWARDS` — см. `.env.example`.

`MODE=copy` (по умолчанию) — пост собирается заново, без пометки «переслано»,
очистка работает. `MODE=forward` — обычная пересылка, текст изменить нельзя.

## 6. Полезные команды

```bash
python -m asdr login      # получить SESSION
python -m asdr check      # проверить доступ к каналам
python -m asdr poll       # один проход (cron)
python -m asdr poll --dry-run   # показать, что было бы опубликовано
python -m asdr watch      # цикл, для VPS
python -m asdr status     # сколько опубликовано и докуда дочитано
python -m asdr test файл  # прогнать очистку по тексту поста
```

## 7. Частые вопросы

**Первый запуск ничего не опубликовал.** Так и задумано: бот начинает с текущего
момента. Чтобы забрать последние N постов при первом запуске, поставьте
`BACKFILL_ON_FIRST_RUN=20`.

**Дубли.** Исключены: хранится id каждого обработанного сообщения плюс хеш
текста (один и тот же пост из двух источников опубликуется один раз).

**FloodWait / «слишком часто».** Бот сам останавливается и продолжит со
следующего запуска. Для спокойной работы хватает интервала 5 минут и
`DELAY_BETWEEN_POSTS=3`.

**Хостинг режет исходящие соединения.** MTProto ходит на порт 443, обычно это
разрешено. Если хостинг блокирует всё, кроме HTTP к своим доменам, вариант один
— перенести бота на VPS или запускать `watch` там, конфиг останется тот же.

**Аккаунт должен быть подписан на источник?** На публичные каналы — не
обязательно, на приватные — обязательно.
