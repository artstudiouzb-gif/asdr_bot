# Установка на хостинг

Проверено на тарифе с PHP 8.5, LiteSpeed, MySQL и cron (hPanel Hostinger).
Займёт около получаса, SSH не нужен — всё через файловый менеджер и панель хостинга.

## 1. База данных

hPanel → **Databases → MySQL Databases** → создайте базу и пользователя.
Запишите: имя базы, имя пользователя, пароль, хост (обычно `localhost`).

## 2. Загрузка файлов

1. Скачайте `reposter-release.zip`, распакуйте у себя — внутри две папки: `reposter` и `panel`.
2. Файловый менеджер → `domains/ВАШ_ДОМЕН/` → загрузите и распакуйте архив так, чтобы получилось:

```
domains/ВАШ_ДОМЕН/
├── reposter/          ← код, недоступен из интернета
│   ├── app/ bin/ db/ vendor/ storage/ public_html/
│   └── .env
└── public_html/
    └── panel/         ← сюда кладётся содержимое папки panel
        ├── index.php  .htaccess  assets/  cron.php  install.php
```

Путь `reposter` загрузчик находит сам — редактировать ничего не нужно.

## 3. Файл .env

В `reposter/` переименуйте `.env.example` в `.env` и заполните:

```env
APP_URL=https://ВАШ_ДОМЕН/panel
APP_KEY=              # 64 случайных символа, см. ниже
TIMEZONE=Asia/Tashkent

DB_HOST=localhost
DB_NAME=имя_базы
DB_USER=пользователь
DB_PASS=пароль

TG_API_ID=            # my.telegram.org → API development tools
TG_API_HASH=

CRON_KEY=             # длинная случайная строка
INSTALL_KEY=          # длинная случайная строка, после установки можно стереть
```

`APP_KEY`, `CRON_KEY`, `INSTALL_KEY` — любые длинные случайные строки (64 символа).
Проще всего взять их из любого генератора паролей.

Права на файл `.env` поставьте **600** (файловый менеджер → Permissions).

## 4. Установка схемы и администратора

Откройте `https://ВАШ_ДОМЕН/panel/install.php?key=ЗНАЧЕНИЕ_INSTALL_KEY`:

1. «Применить миграции» — создаст 16 таблиц.
2. Создайте администратора (логин и пароль от 10 символов).
3. **Удалите `install.php`** из `public_html/panel/` — он больше не нужен.

## 5. Cron

hPanel → **Advanced → Cron Jobs** → добавьте задание с интервалом «каждую минуту»:

```
/usr/bin/php /home/ПОЛЬЗОВАТЕЛЬ/domains/ВАШ_ДОМЕН/reposter/bin/cron.php
```

Если интервал в минуту недоступен, поставьте 5 минут — посты будут выходить с такой задержкой.
Если cron на хостинге умеет только открывать адреса, используйте вместо этого:

```
https://ВАШ_ДОМЕН/panel/cron.php?key=ЗНАЧЕНИЕ_CRON_KEY
```

## 6. Подключение Telegram

1. Войдите в панель: `https://ВАШ_ДОМЕН/panel/`.
2. Раздел **Аккаунты** → укажите название и номер телефона (отдельный, не личный).
3. Через минуту (после запуска cron) статус сменится на «ждёт код» — код придёт в Telegram.
4. Введите код, при включённой двухфакторной защите — пароль.
5. Статус «подключён» означает, что аккаунт готов читать каналы.

## 7. Источники, назначения, маршруты

1. **Источники** — добавьте каналы, откуда берём новости (`@shmirziyoyev` или ссылка).
   Кнопка «Проверить» ставит задание воркеру; результат — на странице «Аккаунты».
2. **Назначения** — ваши каналы. Аккаунт должен быть их администратором,
   а в настройках канала **выключено «Подписывать сообщения»** — иначе Telegram
   подпишет пост именем администратора.
3. **Маршруты** — свяжите источники с назначениями, задайте задержку.

## 8. Проверка работы

* Дашборд показывает время последнего запуска воркера. Если больше 5 минут — cron не работает.
* Страница «Аккаунты» показывает результат последних заданий.
* Журналы: `reposter/storage/logs/` (файлы `app-*.log`, `madeline.log`, `cron.log`).

## 9. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Белая страница | `reposter/storage/logs/app-*.log` — там текст ошибки |
| «Воркер не отвечает» | проверьте задание cron и путь к PHP; запустите вручную адрес `cron.php?key=…` |
| Не приходит код | номер введён в международном формате, аккаунт не заблокирован Telegram |
| «Канал приватный» | аккаунт должен быть подписан на этот канал |
| Ошибка базы | сверьте DB_* в `.env`; хост обычно `localhost` |
| Нужно сбросить пароль администратора | временно верните `install.php`… нет: удалите строку из таблицы `admins` через phpMyAdmin и откройте install.php снова |

## 10. Безопасность после установки

* `install.php` удалён;
* `.env` с правами 600, лежит вне `public_html`;
* каталог `reposter/` недоступен по HTTP — проверьте, открыв `https://ВАШ_ДОМЕН/reposter/`
  (должна быть ошибка 403 или 404);
* файл сессии Telegram (`reposter/storage/telegram/`) — это полный доступ к аккаунту,
  не копируйте его и не выкладывайте.
